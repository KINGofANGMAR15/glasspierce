# TACZ Glass Piercing (glasspierce)

Аддон для **TaCZ (Timeless and Classics Zero)** на **Minecraft Forge 1.20.1**:
одна пуля может пробивать и разрушать **несколько стёкол подряд** (стеклоблоки и стеклянные
панели), каждое разрушение — с **теми же штатными звуком и частицами**, что и в стоке TaCZ.

Ключевые особенности:

- **Лимит по калибру** (`ammoLimits`): 9mm — 1 стекло, 5.56×45 — 2, 7.62×54 — 3, .50 BMG — 5 и т.д.
- **Бонус за улучшения патронов**: экспансивные/HP (+30% урона) добавляют +1 стекло
  (`damageBonusStep`), опционально — бонус за TaCZ-модификатор `pierce` (FMJ).
- **Взрывчатые не трогаются**: RPG-7, 40mm и фугасные (HE) не пробивают стекло —
  они штатно взрываются (тандемная ракета не «застрянет» в стекле без взрыва).
- Все настройки — в серверном конфиге `config/glasspierce-server.toml`
  (в одиночной игре — `saves/<мир>/serverconfig/glasspierce-server.toml`).

---

## 1. Как это устроено в стоковом TaCZ (разбор исходников)

Исходники: `github.com/MCModderAnchor/TACZ`, ветка **`1.20.1`** (релиз `1.1.8-hotfix2`).

### Цепочка попадания в блок

1. `EntityKineticBullet#onBulletTick()` — только серверный тик; рейкаст пути пули:
   `BlockRayTrace.rayTraceBlocks(level, new ClipContext(startVec, endVec, ClipContext.Block.COLLIDER, ...))`.
2. При попадании в блок вызывается
   **`EntityKineticBullet#onHitBlock(BlockHitResult, Vec3, Vec3)`** (~строка 478):

   ```java
   if (MinecraftForge.EVENT_BUS.post(new AmmoHitBlockEvent(this.level(), result, state, this))) {
       return;              // событие отменено -> ранний выход: пуля ЖИВА и летит дальше
   }
   super.onHitBlock(result);
   // ...след пули (BulletHoleOption), воспламенение и т.п. ...
   this.discard();          // событие НЕ отменено: пуля ГИБНЁТ на этом блоке
   ```

3. Событие — `com.tacz.guns.api.event.server.AmmoHitBlockEvent` (отменяемое, серверное).
4. Стоковое разрушение стекла — слушатель
   `com.tacz.guns.event.ammo.DestroyGlassBlock`: при `AmmoConfig.DESTROY_GLASS == true`
   и попадании в `AbstractGlassBlock` / `StainedGlassPaneBlock` / `IronBarsBlock`
   (instrument `HAT`) он вызывает `level.destroyBlock(pos, false, ammo.getOwner())`.

### Откуда берётся ограничение «только 1 стекло»

Две причины, обе подтверждены байткодом:

1. **Нет отмены события.** У TaCZ нет счётчика: стоковый слушатель стекла ломает блок,
   но **не отменяет** `AmmoHitBlockEvent`, поэтому `onHitBlock` доходит до `this.discard()`.
   «Продолжить полёт» можно ровно одним способом — отменить событие.
2. **Телепорт-скачок пули.** В `EntityKineticBullet#tick()` (~строки 267–271) позиция
   обновляется **безусловно**, уже после `onBulletTick()`:

   ```java
   onBulletTick();                       // здесь рейкаст + onHitBlock (наше событие)
   ...
   this.setPos(getX()+x, getY()+y, getZ()+z);   // прыжок на ПОЛНЫЙ deltaMovement!
   ```

   Пуля быстрая (десятки блоков за тик), а рейкаст за тик находит только **первый** блок.
   Поэтому после отмены события на первом стекле пуля «телепортируется» за всю стену
   и следующие стёкла становятся недостижимыми. (Vanilla `clip` при старте луча внутри
   твёрдого блока возвращает «inside-hit» по нему, так что сквозь камень пуля не прошьёт —
   но перепрыгнутые стёкла остаются целыми.) Именно поэтому наш аддон **сам обрабатывает
   весь остаток траектории тика** (см. раздел 3).

### Почему звук/частицы сохраняются автоматически

Звук и частицы разрушения рождает не слушатель TaCZ, а серверная система:
`Level.destroyBlock(...)` транслирует `levelEvent(2001)` (звук битого материала + частицы)
всем клиентам. Стоковый слушатель TaCZ и этот аддон вызывают одну и ту же точку входа —
эффект бит-в-бит как в стоке, без ручного дублирования.

## 2. Два механизма работы (`mode`)

Вся логика вынесена в общий класс `PierceLogic`, механизмы отличаются только точкой входа.

### Вариант A — Mixin (`mode = MIXIN`)

`Mixin@Redirect` на `MinecraftForge.EVENT_BUS.post(...)` внутри
`EntityKineticBullet#onHitBlock` (класс `EntityKineticBulletMixin`).

- Если логика решает «пробиваем» (один или несколько стёкол на пути этого тика),
  mixin возвращает вызывающему коду «событие отменено» → штатный ранний `return`
  без `super.onHitBlock + discard`; разрушение блоков выполняет сам аддон.
- Не-стекло (камень, земля и т.п.) обрабатывается **штатным потоком TaCZ** полностью
  (частицы следа, discard) — аддон не вмешивается.
- Каждый инжектор помечен `require = 0, expect = 0`, `remap = false`: при обновлении TaCZ
  мод молча не применит хук и не крашнется (в режиме `EVENT` продолжает работать listener).

### Вариант B — событие (`mode = EVENT`, по умолчанию)

`AmmoHitBlockListener` слушает `AmmoHitBlockEvent` с приоритетом `HIGHEST`.

- **Основной режим**, потому что: (1) не привязан к внутренностям TaCZ — устойчив к
  обновлениям; (2) отмена события — единственный штатный способ «продолжить полёт»;
  (3) приоритет `HIGHEST` + `receiveCanceled = false` у стокового слушателя гарантируют,
  что стекло не разрушится дважды.
- Отмена события → `onHitBlock` завершится ранним `return` → пуля летит дальше.

### Общий алгоритм (PierceLogic) в обоих режимах

1. **Гейты:** взрывчатый боеприпас (поле `explosion` у пули) → не вмешиваться (штатный
   взрыв); `maxGlassBreaks = 0` → расширение выключено; TaCZ `DestroyGlass отключён` →
   не вмешиваться; блок не «стекло» → не вмешиваться.
2. **Лимит этой пули** (`pierceLimitFor`, кешируется в NBT пули):
   лимит калибра (`ammoLimits`) либо `maxGlassBreaks` (фallback),
   плюс бонус за урон-буст улучшений и опционально за `pierce`.
3. **Перебор траектории внутри тика:** от точки попадания аддон лучом
   (`Level.clip`, `ClipContext.Block.COLLIDER`) проходит остаток пути этого тика
   (длиной `|deltaMovement|`) и последовательно ломает каждое стекло штатным
   `level.destroyBlock(pos, false, owner)`, пока не кончится лимит, не встретится
   не-стекло (пуля гаснет — как в стоке) или не кончатся блоки на пути тика
   (пуля продолжает полёт, остальные стёкла ловятся на следующих тиках).

Счётчик и лимит хранятся в **persistent data самой пули**
(`Entity#getPersistentData()`, тег `ForgeData`, ключи `glasspierce:brokenGlass`
и `glasspierce:limit`): у каждой новой пули свой NBT → счётчик автоматически
сбрасывается при новом выстреле, не перетекает между пулями и не течёт по памяти.

## 3. Конфиг (`glasspierce-server.toml`)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `maxGlassBreaks` | `5` | **Fallback** для калибров, не указанных в `ammoLimits`. `0` — полностью отключить аддон. |
| `ammoLimits` | дефолты стандартного пачка | Лимит по калибру, записи вида `"tacz:9mm"=1`. `0` для калибра = отключить пробитие (сток TaCZ). |
| `damageBonusStep` | `0.3` | Бонус за улучшения патронов: каждые +30% урона сверх базового калибра = +1 стекло (экспансивные/HP ×1.3 → +1). `0` — выключить. |
| `pierceBonusMax` | `0` (выкл) | Опциональный бонус за TaCZ-модификатор `pierce` (+1 стекло за уровень pierce свыше 1; FMJ даёт +2). |
| `allowExplosivePiercing` | `false` | Взрывчатые (RPG-7, 40mm, HE) **не пробивают стекло — штатный взрыв**. Включение не рекомендуется (ракета «застрянет» в стекле). |
| `damageMultiplierPerBreak` | `1.0` | Множитель урона за каждое стекло (0.8 = −20% за блок). Через TaCZ API: `EntityHurtByGunEvent.Pre#setBaseAmount`. Итог = `pow(m, count)`. |
| `velocityMultiplierPerBreak` | `1.0` | Множитель скорости пули за каждое стекло (серверная сущность). |
| `glassBlockTags` | `[forge:glass, forge:glass_panes]` | Дополнительные теги «стекла» (несуществующие теги безопасно игнорируются). |
| `blacklistedBlocks` | `[minecraft:bedrock, minecraft:barrier]` | Блоки-исключения (кроме них автоматически отсекаются блоки с `getDestroySpeed < 0`). |
| `mode` | `EVENT` | Механизм: `EVENT` (вариант B) или `MIXIN` (вариант A). |
| `breakGlassOnLimitReached` | `false` | Лимит исчерпан и пуля упёрлась в стекло: `false` — стекло цело, пуля гаснет; `true` — стекло тоже ломается штатным вызовом, пуля гаснет (поведение стока). |
| `respectTaCZDestroyGlass` | `true` | Если админ TaCZ выключил `AmmoConfig.DestroyGlass`, аддон не вмешивается. |
| `checkTerritoryProtection` | `true` | Если стреляющий игрок: перед разрушением постится синтетический `BlockEvent.BreakEvent`; отмена защитным модом = стекло цело, пуля гаснет. |
| `useVanillaGlassDetection` | `true` | Штатный класс-фильтр TaCZ (AbstractGlassBlock / StainedGlassPaneBlock / IronBarsBlock) в дополнение к тегам. |
| `debugLog` | `true` | Подробный лог решений (первое событие, каждое пробитие, причины отказов и лимиты калибров). После отладки сервера лучше выключить. |

Дефолтные лимиты стандартного пачка TaCZ: `9mm/22wmr/45acp/50ae/57x28/762x25` — 1;
`545x39/556x45/58x42/46x30/762x39/357mag/12g` — 2; `762x54/308/30_06/792x57/68x51fury/45_70` — 3;
`338/500mag` — 4; `50bmg` — 5; `40mm/rpg_rocket` — 0 (взрывные).
Калибры любого другого пачка, не указанные в `ammoLimits`, работают по `maxGlassBreaks`.

## 4. Совместимость

- Mixin-инжекторы помечены `require = 0, expect = 0` (`remap = false`): при обновлении TaCZ
  мод не крашнется, а молча ослабнет до стокового поведения; в режиме `EVENT`
  аддон продолжает работать независимо от mixin.
- Чтение приватных полей пули (`explosion`, `pierce`) — через Accessor-mixin с защитным
  `try/catch`: сбой не ломает механику, аддон продолжит работать с fallback-лимитом.
- При загрузке мода логируется предупреждение, если обнаружены аддоны, которые
  тоже перерабатывают пробитие стекла (`tacz_tweaks`, `tacz_mechanics`,
  `block_durability` / `blockdurability`): функционал по умолчанию не отключается,
  решение оставлено админу.
- Выключение TaCZ'овского `DestroyGlass` уважается (`respectTaCZDestroyGlass`).

## 5. Сборка

```bash
./gradlew build            # jar -> build/libs/glasspierce-1.0.0.jar
./gradlew runServer        # тестовый сервер (config в run/config/)
./gradlew runClient
```

Система сборки: ForgeGradle 6 + MixinGradle (mixin-конфиг подключается
через манифест `MixinConfigs` — см. build.gradle). Зависимость TaCZ подтягивается
из Modrinth Maven (`maven.modrinth:timeless-and-classics-zero:1.1.8-hotfix2`).

## 6. Тестирование

1. Положить jar + **TaCZ 1.20.1** в папку mods (клиент или сервер).
2. В мире поставить **стеклянные блоки подряд в одну линию** (без посторонних блоков
   между ними), например 4 шт. для `tacz:556x45` (лимит 2).
3. Выстрелить через них из винтовки под 5.56×45: лопаются **2 подряд** со штатными
   звуком и частицами, третья остаётся целой, пуля гаснет.
4. Улучшения: тот же калибр с `ammo_mod_hp` (экспансивные, +30% урона, `damageBonusStep=0.3`)
   пробивает **3** стекла (2 + 1 бонус).
5. Взрывчатые: RPG-7 / 40mm / фугасные (HE) **взрываются** на стекле как в стоке
   (тандемная ракета не превращается в «стеклобой»).
6. Повторный выстрел: свежая пуля → лимит заново (счётчик и лимит resetятся — NBT пули).
7. Крайние значения: `maxGlassBreaks = 0` — точное стоковое поведение TaCZ;
   `0` для калибра в `ammoLimits` — сток для этого калибра;
   `blacklistedBlocks` с `minecraft:glass` — пуля вообще не пробивает стекло.
